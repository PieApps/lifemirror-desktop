# 🚀 LifeMirror Desktop: Release & Distribution Process

This document outlines the step-by-step checklist for releasing a new version of LifeMirror Desktop and updating all package managers across Windows, macOS, and Linux.

---

## ⚠️ Golden Rule for AI / LLMs & Developers

> [!CRITICAL]
> **NEVER touch or edit files in `distribution/` when bumping the app version!**
> 
> The files in `distribution/` (`distribution/winget/PieApps.LifeMirrorDesktop.yaml` and `distribution/homebrew/Casks/lifemirror-desktop.rb`) are **static initial starter templates**. 
> - Windows WinGet packages are managed externally via `wingetcreate` against Microsoft's central `microsoft/winget-pkgs` repository.
> - macOS Homebrew Casks are managed externally inside the dedicated `PieApps/homebrew-lifemirror-desktop` GitHub repository.
>
> Touching files in `distribution/` during version bumps is incorrect and has no effect on real users.

---

## 📋 Release Checklist

### Phase 1: Bump Version Numbers (Local Repository)

When bumping the app version (e.g. from `1.3.3` to `1.3.4`):

1. **`src-tauri/tauri.conf.json`**:
   - Update `"version": "1.3.4"`
2. **`package.json`**:
   - Update `"version": "1.3.4"`
3. **`src-tauri/Cargo.toml`**:
   - Update `version = "1.3.4"`
4. **`website/src/constants/links.ts`** *(if updating website download links)*:
   - Update the version string in URLs (`v1.3.4` and `1.3.4`)
5. **Verify build cleanly**:
   ```bash
   npm run build
   cargo check --manifest-path src-tauri/Cargo.toml
   ```
6. **Commit the version bump**:
   ```bash
   git add package.json src-tauri/tauri.conf.json src-tauri/Cargo.toml website/src/constants/links.ts
   git commit -m "chore(release): bump version to v1.3.4"
   git push origin main
   ```

---

### Phase 2: Tag & Push (Triggers GitHub Actions CI)

Create and push the semantic git tag:
```bash
git tag v1.3.4
git push origin v1.3.4
```

**What the automated workflow (`.github/workflows/release.yml`) does:**
1. **Matrix Compilation**: Compiles native binaries for Ubuntu (`.deb`, `.AppImage`), Windows (`.exe`, `.msi`), and macOS (`.dmg`, `.app.tar.gz`).
2. **Draft Release**: `tauri-action` uploads all platform artifacts to a draft GitHub Release.
3. **`finalize-release` Job**:
   - Downloads all release assets from the draft release.
   - Computes a unified `SHA256SUMS.txt`.
   - Attests cryptographic SLSA build provenance with `actions/attest-build-provenance`.
   - Uploads `SHA256SUMS.txt` back to the GitHub Release.

---

### Phase 3: Update Package Managers (Post-CI)

Once the GitHub Actions workflow finishes:

#### 1. Pre-Submit Windows Binary to Microsoft WDSI (Recommended)
Before submitting to WinGet, submit `lifemirror-desktop_1.3.4_x64-setup.exe` to [Microsoft Defender File Submission](https://www.microsoft.com/en-us/wdsi/filesubmission):
- Choose **Software Developer**.
- Attach the setup `.exe`.
- *Why*: Ensures Microsoft static definitions clear the binary before automated WinGet PR scanners run.

#### 2. Update Windows WinGet (Official Package Manager)
Run `wingetcreate` from your terminal:
```powershell
wingetcreate update PieApps.LifeMirrorDesktop --submit --version 1.3.4 --urls https://github.com/PieApps/lifemirror-desktop/releases/download/v1.3.4/lifemirror-desktop_1.3.4_x64-setup.exe
```
This automatically downloads the new binary, computes the hash, generates the version manifest, and opens the PR to `microsoft/winget-pkgs`.

#### 3. Update macOS Homebrew Tap (`homebrew-lifemirror-desktop`)
In your external repository (`https://github.com/PieApps/homebrew-lifemirror-desktop`):
1. Open `Casks/lifemirror-desktop.rb`.
2. Update the `version` line:
   ```ruby
   version "1.3.4"
   ```
3. Update the `sha256` hashes from `SHA256SUMS.txt` in the release:
   ```ruby
   sha256 arm:   "<SHA256_OF_AARCH64_DMG>",
          intel: "<SHA256_OF_X64_DMG>"
   ```
4. Commit and push to `main`.
*(The formula URL automatically updates because it uses `#{version}`).*

---

### Phase 4: Publish GitHub Release Draft

1. Go to `https://github.com/PieApps/lifemirror-desktop/releases`.
2. Review the release draft generated by GitHub Actions.
3. (Optional) Run binaries through [VirusTotal](https://www.virustotal.com/) and paste the permanent scan report link in the release notes.
4. Uncheck **Draft** and click **Publish release**!
